# 要件定義書:「キミ! 今何%!?」判断力測定アプリ「脳でんち」(v1.0 / MVP)

作成日: 2026-07-30 / 対象: Claude Code による実装 / 種別: MVP要件定義書(実装指示書)

> 原文の写し。実装上の不明点への判断は [DECISIONS.md](DECISIONS.md) を参照。

## 0. このドキュメントの読み方

- 本書は MVP(Phase 1) の実装範囲を定義する。Phase 2以降の項目は「実装しない」が、データ設計上の拡張余地は残すこと。
- 「MUST」= MVP必須、「SHOULD」= 可能なら実装、「WON'T(今回)」= 実装禁止(スコープ外)。
- 不明点があれば実装前に質問リストとして提示すること。勝手に仕様を追加しない。

## 1. プロダクト概要

### 1.1 コンセプト

「今」の自分の判断力は、「ベストな状態の自分」の何%か? を1〜2分の認知テストで測定・可視化するセルフコンディション管理アプリ。

- 比較対象は常に過去の自分自身。他人との比較・ランキングは行わない。
- メタファーは「脳のバッテリー残量」。
- キャッチコピー: 「キミ ! 今何%!?」

### 1.2 コアバリュー

- 毎日測りたくなる(1〜2分で完了、結果が一目でわかる)
- 数字が信頼できる(練習効果・時間帯変動への対策を設計段階から組み込む)
- 結果をシェアしたくなる(シェアカード自動生成)

### 1.3 ターゲットユーザー(MVP)

- 夜勤・シフト勤務者、受験生・資格勉強層、生産性に関心の高い個人
- 想定利用シーン: 出勤前・始業前・重要な意思決定の前・飲酒/徹夜後のセルフチェック

### 1.4 このアプリが「やらないこと」(倫理設計・法的制約)

- 医療・診断ではない。認知症スクリーニング等の医療的訴求は一切しない(薬機法対応)。全画面共通フッターまたは初回オンボーディングに「本アプリは医療機器ではなく、診断を目的としません」を明記(MUST)。
- 低スコア時に商品・広告を出さない(MVP時点で広告自体なし。将来もスコア低下時のレコメンドは禁止という設計思想をREADMEに明記)。
- 他者比較ランキングは実装しない(WON'T)。

## 2. 技術スタック・アーキテクチャ(MVP)

| 項目 | 指定 |
|---|---|
| 形態 | PWA(モバイルファースト)。スマホブラウザで完結、ホーム画面追加対応 |
| フレームワーク | Next.js (App Router) + TypeScript + Tailwind CSS |
| 状態管理 | React標準(useState/useReducer) + 必要ならZustand |
| データ保存 | ローカルファースト: IndexedDB(Dexie.js推奨)。MVPではサーバー・アカウント登録なし |
| グラフ | Recharts |
| シェアカード生成 | Canvas API または html-to-image でPNG生成 → Web Share API / ダウンロード |
| 計時精度 | performance.now() を使用(Date.now()禁止)。反応時間はms単位で記録 |
| テスト | Vitest でスコア計算ロジックの単体テスト(MUST) |

設計上の注意:

- 測定エンジン(出題・計時・採点)はUIから分離した純粋関数モジュールとして実装(将来のネイティブ移植・B2B転用を想定)。
- データスキーマにはバージョン番号を持たせ、マイグレーション可能にする。

## 3. 測定エンジン仕様(本アプリの心臓部)

### 3.1 テスト構成:「コア電池」3種(MUST)

1回の測定 = 以下3タスクを連続実行。合計 90〜120秒 に収める。

**Task A: PVT簡易版(心理運動覚醒課題)— 約40秒**

- 画面中央に、ランダム間隔(2〜6秒)でターゲット(大きな円+カウントアップ表示)が出現。出現したら即タップ。
- 試行回数: 8回。
- 記録: 各試行の反応時間(ms)、Lapse(500ms超)回数、False Start(出現前タップ)回数。
- False Start時は警告表示し、その試行は再実行。
- 採用理由: 練習効果がほぼ生じず、覚醒度(眠気)に最も敏感。ベースラインの信頼性の柱。

**Task B: 単純計算 — 約30秒**

- 1桁+1桁、2桁±1桁の加減算を連続出題。回答は4択タップ(誤答選択肢は±1、±10等の近傍値)。
- 制限時間30秒で解けるだけ解く方式。
- 記録: 正答数、誤答数、各問の回答時間。
- 練習効果対策(MUST): 問題はシードベースで動的生成し、同一セッション内・直近セッション間で重複最小化。難易度分布は固定(易:中 = 6:4)し、日によって難易度が揺れないようにする。

**Task C: ストループ課題 — 約30秒**

- 色名の単語(あか/あお/みどり/きいろ)を別の色で表示。「文字の色」を4色ボタンで回答。
- 一致条件:不一致条件 = 1:2 の比率で20問または30秒。
- 記録: 正答数、各問反応時間、不一致条件の干渉量(不一致RT − 一致RT)。

### 3.2 スコア算出ロジック(MUST・単体テスト対象)

各タスクを「正確性 × 速度」の複合スコアにする。

```
Task A (PVT):  scoreA = 1000 / meanRT(ms) を基準に、Lapse 1回につき −5%、FalseStart 1回につき −3% のペナルティ
Task B (計算): scoreB = 正答数 / 経過秒 × 正答率補正(正答率^1.5)
Task C (ストループ): scoreC = 正答数 / 経過秒 × 正答率補正(正答率^1.5) × 干渉量補正
総合スコア(重み): S = 0.40 × normA + 0.30 × normB + 0.30 × normC
(normX = 各タスクスコアをベースライン比に正規化した値。重みは設定ファイルで変更可能にする)
今日の判断力% = round( S ÷ ベースラインS × 100 )
```

- 表示上限は 105% でクリップ(それ以上は「絶好調!」表示)。下限は表示なし(実値表示)。
- 外れ値処理: 各タスク内で反応時間の上下5%タイル外はトリム平均。

### 3.3 ベースライン(=自分の100%)仕様

これが本アプリの根幹。以下を厳密に実装すること。

**(a) 7日キャリブレーション「ベスト計測ウィーク」(MUST)**

- 初回起動から7日間を「自分の全盛期を記録する週」として演出。
- 本人ベースライン = 7日間のセッションのうち上位3セッションの平均(単一最高値は使わない。まぐれ・外れ値対策)。
- Day 7完了時に「キミの100%! 確定!!」画面を表示(→ 6.4 シェアモーメント②)。

**(b) 暫定ベースライン(MUST)— Day 1離脱対策**

- 初日から%を表示するため、初回測定の直後から暫定基準で%を出す。
- 暫定基準 = アプリ内蔵の標準参照値テーブル(年代 × 時間帯別のプリセット定数。オンボーディングで生年代を任意入力、未入力時は全体標準値)。
- 暫定期間中は%の横に「推定」バッジを常時表示し、タップで説明を出す。Day 7で本人基準に自動切替。

**(c) 時間帯別ベースライン(SHOULD)**

- 測定時刻を朝(4-11時)/昼(11-17時)/夜(17-24時)/深夜(0-4時)の4区分で記録。
- 十分なデータ(各区分3セッション以上)が溜まった区分は、区分別ベースラインで%を算出。未達の区分は全体ベースラインを使用し、その旨を小さく表示。
- 夜勤ユーザー対応: オンボーディングで「夜勤・シフト勤務ですか?」を質問し、YESの場合は深夜区分の測定を促す文言に切替。

**(d) ベースライン更新(MUST)**

- 確定後も、本人ベースラインを上回るスコアが出た場合は「ベスト更新!」演出とともにローリング更新(直近90日の上位3平均)。練習効果によるインフレを「ベスト更新の喜び」として吸収する設計。

## 4. 画面仕様(MVP: 6画面)

### 4.1 オンボーディング(初回のみ)

- 3枚のスライド: ①コンセプト(「キミ!今何%!?」) ②7日で自分の100%が決まる説明 ③免責(医療目的でない・データは端末内保存)
- 任意入力: 年代、夜勤有無、通知時刻(SHOULD: Web Push。難しければローカルリマインダー文言のみ)

### 4.2 ホーム

- 中央に大型円形ゲージ(グラレコのメーターデザイン踏襲): 本日の%を大きく表示。未測定時は「?」+「測定する」ボタン。
- ゾーニング表示(MUST):
  - 90%以上: 緑「今、勝負をかける時」
  - 70〜89%: 黄「通常運転」
  - 70%未満: 橙「重要な決定は避けて。休憩推奨」
  - 50%未満: 赤「今日は休養日。運転・重要判断は特に注意」
- キャリブレーション期間中は進捗表示「ベスト計測ウィーク Day 3/7」。

### 4.3 測定フロー

- 開始前カウントダウン(3秒) → Task A → B → C を自動遷移。中断したセッションは無効として保存しない。
- 測定中は他UI要素を排除(没入設計)。

### 4.4 結果画面

- %をアニメーションで表示 → ゾーン別メッセージ → タスク別内訳(覚醒度/処理速度/切替力の3レーダーまたは3バー)。
- 「シェアカードを作る」ボタン(→ 6章)。

### 4.5 履歴・トレンド

- 折れ線グラフ(直近7日/30日切替)、時間帯別平均バー、測定一覧。
- 無料/有料のゲーティングはMVPでは実装しない(全機能開放)。ただしコード上、機能フラグで区切れる構造にすること(SHOULD)。

### 4.6 設定

- 年代・夜勤設定の変更、ベースラインの説明表示、ベースライン再計測(全リセットは確認2段階)、データ全削除、免責事項。

## 6. シェアカード機能(MUST — グロースの生命線)

### 6.1 生成仕様

- 結果画面から1タップでPNG生成(1080×1350px、縦型)。
- 構成: ①大型%数字+円形ゲージ ②「本日の判断力(全盛期比)」 ③日付 ④下部に「→ 次はキミ!今何%!?」+アプリ名「脳でんち」/ロゴ ⑤ハッシュタグ「#今日の判断力 #今何パーセントチャレンジ」
- 配色はゾーン連動(緑/黄/橙/赤)。数字は画面の40%以上を占める大きさ。

### 6.2 シェア手段

- Web Share API(対応時)、非対応時は画像ダウンロード+テキストコピー。

### 6.3 プライバシー

- カードには%と日付以外の個人情報を一切載せない。

### 6.4 シェアモーメントは2つ

- ① 毎日の測定結果カード
- ② Day 7「キミの100%、確定。」記念カード(専用デザイン: トロフィー演出)

## 7. 非機能要件

- パフォーマンス: 測定中のタップ→記録遅延を最小化。アニメーション等はrequestAnimationFrame、入力はpointerdownで計時。
- オフライン動作: Service Workerで完全オフライン測定可能(MUST)。
- アクセシビリティ: ストループの色は色覚多様性を考慮し、色+ボタン位置固定+ラベルで冗長化。
- プライバシー: MVPは外部送信ゼロ。アナリティクスも入れない(READMEに明記)。
- 多言語: MVPは日本語のみ。文言はi18n構造(辞書ファイル分離)で実装(SHOULD)。

## 9. 受け入れ基準(Acceptance Criteria)

1. 初回起動→オンボーディング→初回測定→暫定%表示(推定バッジ付き) まで3分以内に完了できる
2. 7セッション完了時に「100%確定」画面が表示され、以後の%が本人基準で算出される
3. 同一条件の入力に対しスコア計算が決定論的である(単体テストで検証)
4. PVTの反応時間が±10ms精度で記録される(performance.now使用の確認)
5. シェアカードPNGが生成され、Web Share APIまたはダウンロードで取得できる
6. 機内モード(オフライン)で測定〜結果表示が完了する
7. 免責事項(非医療)がオンボーディングと設定画面に表示される
8. 低スコア時にいかなる商品・外部リンクも表示されない

## 10. 実装順序の推奨

1. 測定エンジン(純粋関数)+単体テスト
2. 測定フローUI(Task A→B→C)
3. ベースラインロジック(暫定→7日確定→更新)
4. ホーム/結果/履歴画面
5. シェアカード生成
6. オンボーディング/設定/免責
7. PWA化(Service Worker、manifest)
